# 途策 AI 智能选校 · 部署交接说明

交付日期：2026-09-03。部署方式：独立测评站 + 官网入口按钮。无需取得官网源码即可先部署；官网维护人最后添加链接或脚本即可。

本材料是部署准备包，不代表已正式上线。ai.tuce.asia 仅是域名示例，需取得域名管理人的确认并完成解析。临时 trycloudflare 链接不作为正式地址。

## 1. 请负责人确认的事项

- 服务器：可运行 Docker Engine 和 Docker Compose 插件，具备持久磁盘和外网访问能力；提供部署负责人或授权的操作渠道。
- 域名：确定测评子域名，并由 DNS 管理人配置到服务器公网 IP。若配置 AAAA，IPv6 也必须正确可达。
- 端口：专用服务器使用 80/443；若已有官网或其他代理占用这些端口，采用本文“已有网站服务器”方案。
- AI 账户：有效的 DeepSeek API Key、可用额度及费用负责人。
- 管理人员：指定后台使用者，单独设置正式后台强随机口令；不要沿用本地测试口令。
- 通知：可选企业微信群机器人地址，或 SMTP 服务器、发件账号及授权码、收件顾问邮箱。
- 官网维护人：负责添加按钮，检查手机端位置，并处理网站的脚本加载策略。

密钥通过受控渠道交给部署人或直接在服务器填写，不放进官网代码、压缩包或公开仓库。通知未配置时，留资仍会保存，但不会自动推送。

## 2. 包内文件

- `Dockerfile`：Python 应用镜像，包含页面与后端。
- `deploy/compose.yaml`、`deploy/Caddyfile`：专用服务器部署及 HTTPS 配置。
- `deploy/compose.existing-proxy.yaml`：已有网站服务器的应用部署配置。
- `agent/.env.example`：空白配置模板。
- `agent/app`、`web/static`：当前应用代码与页面，包含 AI 文案、留资后台和清除历史留资功能。
- `scripts/backup_db.py`：SQLite 一致性备份工具。
- `agent/tests`：自动化测试；AI 和通知使用测试替身。
- `官网入口接入.txt`：交给官网维护人的按钮代码。
- `SHA256SUMS.txt`：包内文件校验清单。

不包含真实 .env、API Key、后台口令、数据库、历史留资、备份或虚拟环境。首次部署使用空数据库。

## 3. 专用服务器部署

以下命令均在解压后的项目根目录执行。先安装并确认 Docker Engine 与 Compose 插件可用；服务器需能访问镜像仓库、Python 包源、DeepSeek 和证书服务。

```sh
cp agent/.env.example deploy/.env
chmod 600 deploy/.env
```

在服务器编辑 `deploy/.env`，至少填写：

```text
DEEPSEEK_API_KEY=填写有效密钥
ADMIN_TOKEN=填写至少32字符的随机口令
EVALUATION_DOMAIN=填写实际测评域名（不含https和路径）
```

可用 `openssl rand -hex 24` 生成管理口令，再存入受控密码管理工具。其他配置按模板填写。

域名解析正确、80/443 未被占用且防火墙放行后执行：

```sh
docker compose --env-file deploy/.env -f deploy/compose.yaml config --quiet
docker compose --env-file deploy/.env -f deploy/compose.yaml up -d --build
docker compose --env-file deploy/.env -f deploy/compose.yaml ps
```

Caddy 自动申请 HTTPS。应用端口不直接对公网开放；SQLite 保存在 Docker 命名卷中。访问实际域名的 `/` 为测评页，`/admin` 为后台，`/health` 为健康检查。

## 4. 已有网站服务器

如果现有 Nginx/Caddy 已占用 80/443，不要启动上面的专用服务器模板。使用独立应用配置：

```sh
docker compose --env-file deploy/.env -f deploy/compose.existing-proxy.yaml config --quiet
docker compose --env-file deploy/.env -f deploy/compose.existing-proxy.yaml up -d --build
```

该配置只绑定服务器本机 `127.0.0.1:18000`。由原服务器维护人新增测评域名的 HTTPS 站点并反向代理到该地址，同时设置：请求体上限 16KB、禁用 iframe 嵌入，禁止外部访问 `/docs`、`/redoc`、`/openapi.json`、`/api/v1/ping-deepseek` 和 `/integration-preview.html`。代理超时建议覆盖 AI 重试耗时（至少 200 秒）。

此方案默认不信任转发头，按统一来源进行保守限流。维护人应根据真实网络路径配置可信代理和真实客户端 IP 后再开放；不得无条件信任客户端提供的转发头。若代理本身运行在另一个容器中，127.0.0.1 并非宿主机地址，需要维护人调整容器网络，不要直接把应用端口暴露公网。

两种部署方案择一使用，切换方案时需要明确数据卷位置并执行迁移，不能假定数据自动共享。

## 5. 上线验收

- 外部网络打开主页，页面正常，HTTPS 证书有效；`/health` 返回 `{"status":"ok"}`。
- 填写一组明确标记为测试的背景，确认生成三档、每档两校；未留资时不展示推荐理由。这一步产生真实 AI 调用费用。
- 使用经负责人同意的测试联系方式完成解锁，确认后台出现记录且报告可查看；开启通知时确认顾问实际收到通知。
- 错误或空管理口令不能读取留资；正确口令可查看并导出 CSV。
- “清除历史留资”会删除全部线索，仅在空测试环境验证，不能在已有正式数据时用来删除单条测试记录。
- 重启应用后确认留资仍存在；完成一次备份及恢复演练。
- 官网按钮在电脑和手机端可点击、无遮挡，链接到正式测评域名。
- 上线负责人确认隐私告知、联系方式使用范围、数据保存期限和删除流程；明确 AI 建议未经实时招生信息核验。

健康检查仅证明应用能响应，不代表 AI、通知或推荐准确性已验收。后台目前是共享口令制，建议由维护人限制管理入口访问范围。单实例限流不等同于 AI 费用封顶。

## 6. 备份、更新与恢复

下列示例为专用服务器方案；已有代理方案请把配置文件名换成对应名称。

```sh
mkdir -p backups
chmod 700 backups
docker compose --env-file deploy/.env -f deploy/compose.yaml exec -T app python - --source /app/data/leads.db --output-dir /tmp < scripts/backup_db.py
```

命令会打印备份文件路径。用实际输出的文件名替换下面的占位内容：

```sh
docker compose --env-file deploy/.env -f deploy/compose.yaml cp app:/tmp/实际备份文件名.db backups/
chmod 600 backups/实际备份文件名.db
```

备份包含个人联系方式，应转移到受控的备份存储，并由维护人安排定期备份、保留周期和恢复演练。容器 /tmp 不是长期备份位置。

更新前备份并保留旧版本材料，再执行 `up -d --build`。故障时先看 `docker compose --env-file deploy/.env -f deploy/compose.yaml logs --tail=100 app caddy`，分享日志前检查是否含个人信息。

恢复需由维护人先停止应用，将备份导入正确的数据卷，恢复文件属主为应用用户 UID 10001，再启动验证；先在隔离环境演练。发生结构变化时不能仅替换旧代码，应同时评估备份的数据结构兼容性。

**不要执行 `docker compose down -v`，它会删除数据卷。** 本地已有留资如需迁移，另行确认后处理，未包含在本包中。
